상단바 통일 변형 비교 (A · B · C · D)

현재 상단바에는 선택 언어 3종이 공존합니다 — 탭(밑줄+SemiBold) · 사이드바 트리(카드+앰버 틴트, 10-03 승인 D안) · 라이브러리 Grid/List 토글(세그먼트 칩). 여기에 앱 어디에도 없는 텍스트 구분자 |, 4의 배수가 아닌 간격(2·6·8·10·14), 그리고 높이 불일치(바 40 vs 캡션 32)가 겹쳐 통일감이 깨집니다. 아래 4안은 공통 리듬 정리(구분자 제거 → 간격 12, 탭 간격 4, 높이 일치)를 깔고 탭의 시각 언어를 무엇에 맞출지만 다릅니다. 탭과 사이드바 행을 클릭하면 상태가 바뀌고, 오른쪽 위 스위처에서 높이 3상태(현상 포함)를 비교할 수 있습니다.

높이캡션 32px vs 바 40px — 8px 괴리 (스크린샷 빨간 선 지점)

시스템 캡션 버튼(─ □ ✕)은 TitleBarHeightOption.Standard(32px)로 그려지는데 상단바 행은 40px(MinHeight + Grid 행)라서, 캡션의 호버 배경·글리프가 바 하단에 8px 못 미치고 뜨고 캡션 중심(16px)과 앱 콘텐츠 중심(20px)도 어긋납니다. 위 스위처에서 세 상태를 비교해 보세요. 문서(/windows/apps/develop/title-bar)의 수정책은 AppWindow.TitleBar.PreferredHeightOption로 둘을 일치시키는 것 — Tall(48px)은 인터랙티브 콘텐츠(메뉴·탭·톱니)가 있는 타이틀바의 문서 권장 높이라 캡션이 바를 꽉 채우고, Standard(32px)는 바를 캡션에 맞춰 줄입니다(컴팩트하지만 28px 칩· 32px 버튼이 빠듯). 구현 범위(공통): 생성자에서 PreferredHeightOption = TitleBarHeightOption.Tall (문서 경고 — ExtendsContentIntoTitleBar=true 이후 설정) + XAML 행·MinHeight 40→48 + 미니 모드 복원의 하드코딩 40 → 상수 1곳 통일. 단계 숨김(840/740)은 폭 기준이라 무영향.
