## 현재 수준 요약

제안 작성 시점의 구현 상태 (README.md 기준):

- **오디오 엔진**: WASAPI 배타 출력(공유 폴백), 갭리스 시퀀서, MP3/AAC/ALAC/FLAC/Ogg Vorbis/WAV,
  8밴드 파라메트릭 EQ(장치별 프로필), ReplayGain + AGC 하이브리드 노멀라이저, 크로스피드/모노 다운믹스,
  28밴드 실시간 스펙트럼, 소프트 리미터, EBU R128 라우드니스 스캐너
- **재생목록**: 다중 탭 + M3U8, 스마트 재생목록(청취 통계 SQLite 기반, 고정 3종), 트랙 대기열,
  셔플/반복/A-B 반복, 정렬·중복 제거·그룹 묶기
- **라이브러리**: 폴더 색인(SQLite 증분 스캔), 아티스트/앨범/장르 필터, 태그 편집기,
  ReplayGain 일괄 분석, 앨범아트 캐시, 커버 그리드/목록 보기
- **가사**: .lrc 동기 가사 + 온라인 가사 플러그인 SDK(LRCLIB 샘플), LRC 에디터
- **UI/인프라**: Eole 스타일 × WinUI 3, 3개 국어 i18n, SMTC, 단축키 재할당, 수면 타이머,
  트레이 통합, Inno Setup 인스톨러 + 포터블 ZIP, 단위 테스트 1,253+

## 1. Quick Wins — 기존 인프라를 재사용해 낮은 비용으로 큰 효과

> **✅ 2026-09-03 구현 완료** — 1단계 4개 항목 모두 구현·테스트 완료 (빌드 0 경고, 단위 테스트 1,629 통과).
> 세부 사항은 각 항목 하단의 메모 참고.

### 1.1 ReplayGain 2.0 태그 지원
- `LoudnessScanner`(−18 LUFS)가 이미 있는데 태그 포맷만 옛 RG 1.0(`REPLAYGAIN_*`)이다.
- 스캐너 결과를 `R128_TRACK_GAIN` / `R128_ALBUM_GAIN`으로도 쓰고 읽도록 양쪽 지원.
- 스캐너 로직 재사용이라 구현량이 작다.
- ✅ 구현: `TagWriter.TrySetReplayGain(writeR128:)` + 설정 토글(환경설정 → 라이브러리),
  `TagReader`는 RG1 필드가 없으면 R128 값을 LU→dB 그대로 폴백 읽기.

### 1.2 트랙 평점(rating) 시스템
- 통계가 이미 SQLite에 있으므로 `rating` 컬럼 추가만으로 시작 가능.
- 재생목록 행에 별 표시, `ID3v2 POPM` / Vorbis `RATING` 태그와 동기화.
- 스마트 재생목록의 표현력이 크게 올라간다.
- ✅ 구현: 라이브러리 스키마 v3(`rating` 컬럼 + `play_events` 테이블), `PlaylistItem.Rating` 통지 프록시,
  재생목록 행 별 표시 + 컨텍스트 메뉴 일괄 지정, 태그 양방향 동기화(POPM 앵커 1/64/128/196/255,
  Vorbis/MP4 RATING 스케일 적응 읽기), 리스캔 시 평점 유지.

### 1.3 스마트 재생목록 쿼리 언어
- 현재는 "많이 재생 / 최근 추가 / 한동안 안 들은" 고정 3종.
- foobar 스타일 쿼리(예: `%rating% GREATER 3 AND %last_played% DURING LAST 30 DAYS`)를 파서로 제공.
- Core에 순수 파서로 넣으면 xUnit 테스트도 깔끔하게 붙는다.
- ✅ 구현: `SmartPlaylistQuery`(재귀 하강 파서 + 평가기 — IS/HAS/!=/부등호/MISSING·PRESENT/
  DURING LAST n DAYS|WEEKS|MONTHS/AND·OR·NOT/괄호/LIMIT n), 생성·편집 다이얼로그(실시간 검증),
  정의는 `settings.json`에 영속, 내장 3종과 구분되는 사용자 스마트 재생목록(편집·삭제 가능).

### 1.4 청취 리포트 대시보드
- 재생 통계 DB + 앨범아트 캐시 + `AlbumArtColorExtractor`가 이미 있음.
- "이번 달 top 아티스트/앨범, 청취 시간, 트렌드" 뷰(Spotify Wrapped 라이트).
- 재료가 전부 준비되어 있는 상태.
- ✅ 구현: `play_events` 이력 테이블(집계 컬럼과 별도 시간축 데이터), `ListeningReportBuilder`
  (순수 집계 — 결정적 랭킹), 타이틀 메뉴 → 청취 리포트 다이얼로그(전체/최근 30일/올해 기간 선택,
  총 재생·청취 시간·top 아티스트/앨범/장르/곡).

### 1.5 웨이브폼 시크바 / 풀스크린 비주얼라이저
- DSP 체인 끝의 `SpectrumTapDspEffect` 재사용.
- 시크바에 전체 트랙 웨이브폼 표시(디코딩 시 한 번 캐시)하거나 28밴드 스펙트럼의 풀스크린 확장.
- 시각화 계열 확장이 구조적으로 쉽다.

## 2. 오디오 엔진 고도화

### 2.1 CUE 시트 지원
- 단일 FLAC 이미지 + `.cue` 재생은 오디오파일 유저의 핵심 요구.
- `AudioFileReaderFactory` 레벨에서 가상 트랙 분할 + 갭리스 시퀀서와 자연스럽게 맞물림.
- 난이도 대비 만족도가 가장 높은 엔진 항목.

### 2.2 포맷 확장: Opus, APE, WavPack, DSF/DFF
- Opus는 인터넷 라디오의 사실상 표준이라 2.3의 전제.
- DSF는 배타 모드와 결합해 DoP/DSD 네이티브 출력까지 가면 차별화 포인트.
- NVorbis처럼 관리형 라이브러리 조합으로 가능.

### 2.3 인터넷 라디오
- Icecast/Shoutcast HTTP 스트림 재생 + 방송국 즐겨찾기.
- 스트리밍 소스가 `SequencerStream` 체계에 들어가면 재생목록/SMTC/대기열이 그대로 재사용됨.

### 2.4 컨볼버(임펄스 응답) DSP
- `IAudioDspEffect` 슬롯 하나 추가로 룸 보정/헤드폰 IR 적용.
- DSP 체인이 이미 플러거블해서 스펙트럼 탭 앞에 끼우기만 하면 됨.

### 2.5 고품질 리샘플러
- 배타 모드에서 출력 장치 레이트와 음원 레이트가 다를 때 세션 재구성 대신 고품질 ASRC를 옵션으로 제공.
- 장치 호환성 개선.

## 3. foobar DNA 계열 — 파워유저를 위한 깊이

### 3.1 오디오 변환기(Transcoder)
- foobar의 시그니처 기능. FLAC→Opus/MP3 변환 시 DSP 체인·ReplayGain·메타데이터·앨범아트까지 적용해 내보냄.
- 구현량은 크지만 태그 편집기·R128 스캐너·DSP 체인이 모두 재사용되어 준비 상태는 좋음.

### 3.2 파일 정리(File Operations)
- `%artist%/%album%/%track% - %title%` 패턴으로 파일 이동/이름 변경.
- 태그 편집기와 같은 메타 인프라 공유.

### 3.3 재생목록 실행 취소/다시 실행 + 잠금
- 대형 라이브러리 관리 작업(정렬, 중복 제거, 드래그)의 안전망.

### 3.4 AcoustID/MusicBrainz 자동 태깅
- 오디오 지문으로 메타데이터 보정.
- `TagWriter`가 이미 원자적 저장을 하므로 쓰기 경로는 안전.

## 4. UI/UX 고도화

- **미니 플레이어 / 항상 위 컴팩트 모드** — 트레이·SMTC와 함께 "백그라운드 플레이어" 완성도 상승.
- **트랙 변경 토스트 알림** — 트레이로 숨겨둔 상태에서 앨범아트+메타 표시. `TrayIconService`와 자연스럽게 연결.
- **라이브러리 퍼지 검색 / 전체 필드 검색** — 아티스트/앨범/장르 필터에 더해 모든 메타 필드 대상 통합 검색.
- **재생 중 앨범 배경 블러** — `AlbumArtBlurHelper`가 이미 존재. 설정 옵션으로 노출만 추가하면 됨.

## 5. 생태계 확장

- **Last.fm 스러블링** — 청취 통계 훅에 부착. 국내외 오디오 유저층의 실질적 요구.
- **DSP/컴포넌트 플러그인 SDK 확장** — 가사 플러그인 아키텍처(`DawnPlayer.Plugin.Abstractions`)를
  DSP 이펙트·메타데이터 프로바이더로 확장. "foobar 스타일 컴포넌트 생태계" 포지션 완성.
- **HTTP/WS 원격 제어 API** — 스마트폰 리모컨 앱, Stream Deck 연동.
